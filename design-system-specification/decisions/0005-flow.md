# 0005 — Flow

## Context

Flow is the vertical space between blocks of content, such as a heading and its paragraph, or one card and the next.

Longform and product interfaces need different densities, but contexts can nest. A fixed gap that suits one context looks wrong in another.

Vertical rhythm used to be set partly by typography and partly by hand-placed margins in a product context. We needed a unified way to set it, with density taken from the context and component spacing protected from outside rules.

## Decision

- **Flow sets the space between blocks.** Typography does not set space itself: `typeset-longform` automatically adds the `flow-spacious` context, and flow supplies the space ([0003](./0003-typography.md)).
- **There are three flow contexts:** `flow-spacious`, `flow-standard` and `flow-compact`. Standard is the default. `typeset-longform` sets `flow-spacious`, and `typeset-product--formatted` sets `flow-standard` ([0015](./0015-system-classes.md), [0016](./0016-flow-in-system-css.md)).
- **The context defines the value of the step.** There are four steps: `tight`, `default`, `loose` and `section`.
- **Choose the context by the space available.** `flow-compact` is for surfaces too small to show four distinct gaps, such as control panels, map overlays, tooltips and dense sidebars. In it, `tight` equals `default` and `loose` equals `section`. Other product surfaces use `flow-standard`, and reading content uses `flow-spacious` through `typeset-longform`.
- **Flow assigns steps from the markup in every flow context.** The same rules apply in `flow-spacious`, `flow-standard` and `flow-compact`, and in the contexts the typesets set. Each direct child after the first gets a step from its element or role class:
  - Any child takes `default`.
  - A block object (`figure`, `img`, `table`, `pre`, `blockquote` or `.chart`) takes `loose`, and so does the child after it.
  - A major heading (`h1`, `h2`, `display-*`, `headline-*` and the dashboard title aliases) takes `section`.
  - A minor heading (`h3` to `h5`, `title-*` and the card, chart, table, header and sidebar title aliases) takes `loose`. Headings below `h5` are discouraged, so `h6` has no rule and takes `default`.
  - Inside a direct child, list items and nested lists take `tight`. In a `dl`, each `dd` takes `tight` and each `dt` after the first takes `default`.
- **Parts that belong together are coupled at the `tight` step.**
  - A title group: a heading straight after another heading, a subtitle (`subhead-*`, `subtitle-*` or a subtitle alias) straight after its heading, and a heading straight after its eyebrow ([0012](./0012-title-groupings.md)). An eyebrow before a major heading takes the `section` step, so the group is set off as one.
  - A caption and what it captions: `figcaption` in a `figure`, `caption` in a `table`, and a caption role or `.chart-note` straight after a block object.
- **There is no separate hero spacing.** The space above display type is the `section` step, or comes from the layout.
- **Authors override a step with a utility.** `mt-flow-{step}` sets the space above one element and replaces the step the rules gave it. `gap-flow-{step}` sets the gap between the children of a flex or grid container that is not itself a flow context. A context class and `gap-flow-*` on the same element add together, so they are not combined.
- **Flow spaces only the direct children of its context.** A component's insides are never direct children of the outer context, so outer flow spaces the component's root and goes no further. No class is needed to seal a component. A component declares its own context only to set the density of its own children, and it then keeps that density wherever it is placed.

## Options considered

- **One ramp of four steps, with density set by context** (chosen)
- **Utilities named by context (`.mt-flow-spacious-loose`).** Withdrawn. A component using them would bring a fixed density into any context it was placed in. The correct usage is (`.mt-flow-loose`) within a `.flow-spacious` context.
- **Making author-set steps win through higher specificity.** Not adopted. Each new rule would push specificity higher. An exclusion in each rule's selector keeps every rule at the same weight.
- **Assigning steps from the markup in `typeset-longform` only.** Not adopted. Product content uses the same headings, figures and lists, and one set of rules is easier to predict.
- **Sealing a component when it declares any padding or gap.** Not adopted. The direct-children rule already stops outer flow at the component's root.
- **A hero step above display type.** Dropped. `section` gives enough space, and a larger space belongs to the page layout.

## Consequences

- Values and the context classes live in flow.css (generated from Figma). The spacing rules live in tailwind-custom/flow/flow.cjs; the `mt-flow-*` and `gap-flow-*` utilities in tw-extend/flow.cjs.
- internal variables (generated by style dictionary):`--flow-tight`, `--flow-default`, `--flow-loose` and `--flow-section` are set on :root (pointing at standard) and switched by each context class.
- Attention has to be paid to nested structures. A wrapper element between the context and the blocks gets the space, and the blocks inside it get none.
- The full table of element, role and step is generated into the spec from the build, so it can't drift from the rules.
- Two caption couplings are not built yet. A table `caption` has a fixed `padding-bottom` of `--spacing-2` in `sd/content.css`, and a caption role or `.chart-note` after a `.chart` takes `loose`.
- Use flow for vertical rhythm between siblings inside a container, set once on the parent so content can change without anyone touching spacing (as when using markdown); use spacing classes for horizontal spacing, padding, and component internals.
