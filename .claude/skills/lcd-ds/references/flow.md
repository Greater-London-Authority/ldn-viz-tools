# Flow & vertical rhythm

Distilled from the spec's _Content Flow_ section. Verified against branch `flow`.

**Code anchors:**

- `packages/themes/tailwind-custom/flow/flow.cjs` — the selector rules (behaviour)
- `packages/themes/tailwind-custom/flow/index.cjs` — the standalone Tailwind plugin
- `packages/themes/styles/flow.css` — emitted ramp (values), generated by `custom/flow` in `sd.build.js`
- `packages/themes/styles/tw-extend/flow.cjs` — the four utility keys, wired into `ldn-theme.cjs`

> Flow moved **out of** the typography plugin. It is a layout system, not a
> typographic one, and registers as a peer of `customTypography` (immediately
> before it, to preserve cascade order). Anything still pointing at
> `tailwind-custom/typography/flow.cjs` is stale.

## Principle

Vertical rhythm is a property of the **context**, not of the type inside it. Never
bundle margin onto a role. An author declares a context; the gaps that can be
inferred are inferred, and the rest are named — never measured.

> **Flow spaces a stack. Prose stacks are typographic and the system assigns rungs
> for you. Product stacks are blocks and you assign the rung yourself — from the
> same four names.**

In prose the DOM declares what each element is (`h2` announces itself), so rules
infer the rung. In a dashboard every block is a `div` carrying no relational
information, so nothing can be inferred and only the base rule fires — which is
why `flow-product` looks like it "does nothing but apply a uniform 8px".

## The four-step ramp, remapped per context

| Rung             | `flow-prose` | `flow-product` | `flow-compact` |
| ---------------- | ------------ | -------------- | -------------- |
| `--flow-tight`   | 4            | 4              | 4              |
| `--flow-default` | 16           | 8              | 4              |
| `--flow-loose`   | 24           | 16             | 8              |
| `--flow-section` | 40           | 24             | 8              |

**A rung carries a relationship, never a density.** Density comes from context.

`flow-compact` (toasts/tooltips/alerts/dialogs) deliberately collapses the ramp to
two effective values — `tight` = `default`, `loose` = `section`. Not a bug; do not
"fix" it. A new density is one new context remapping four variables.

**The context class is both the variable scope AND the flow root** — `flow-prose`
alone; there is no separate bare `.flow` class. Two-class markup (`class="flow
flow-product"`) is wrong and appears in older docs.

`flow-*` sets rhythm vars only. Type vars come from the separate `.prose` /
`.product` / `.chart` context class — see `references/typography.md`. A dashboard
surface normally carries both: `class="product flow-product"`.

## What is emitted (two hops)

```css
:root {
	--flow-prose-tight: 0.25rem; /* 12 flat vars: 3 contexts × 4 rungs — */
	--flow-product-default: 0.5rem; /* the single value source              */
	/* … */
	--flow-tight: var(--flow-product-tight); /* product is the library    */
	--flow-default: var(--flow-product-default); /* default density, so the */
	--flow-loose: var(--flow-product-loose); /* four rungs always resolve */
	--flow-section: var(--flow-product-section);
}

.flow-prose {
	--flow-tight: var(--flow-prose-tight); /* … */
}
```

Context blocks **reference** the flat vars rather than restating them. Nothing in
the ramp is hand-written in CSS and nothing in a component should restate a rung's
value — if a gap is wrong it is wrong in Figma, and fixing it there fixes it
everywhere.

The `:root` product ramp means `mt-flow-section` outside any context still resolves
(to 24px) rather than falling back to `0`. `.flow-*` classes stay meaningful because
they also **arm the rules**, which `:root` cannot do.

## Author-facing utilities

Four keys, exposed through the theme's `margin` and `gap` keys:

```
mt-flow-tight    mt-flow-default    mt-flow-loose    mt-flow-section
gap-flow-tight   gap-flow-default   gap-flow-loose   gap-flow-section
```

- `mt-flow-*` → the element needing the gap **above** it.
- `gap-flow-*` → a flex/grid container spacing its children — a container that is
  **not** itself a flow context (else the owl's `margin-top` and the `gap` add up).
- **No `p-flow-*`**, deliberately: flow keys are in `margin`/`gap`, never `spacing`.
  Padding is construction.
- **No context-prefixed utilities.** `mt-flow-product-section` does not exist —
  withdrawn. It is `mt-6` wearing a flow badge: it pins one gap to a fixed density
  and opts the element out of the rhythm around it. A component needing fixed
  density declares **its own context class** instead.
- **Known looseness:** the `margin` theme key also generates `mb-`/`mx-`/`ml-flow-*`.
  Nothing keys on them and they contradict the vertical-only ruling. Use `mt-` and
  `gap-` only. OPEN item, not a bug to re-report.

## Author-declared beats DOM-inferred

Every sibling rule carries `[class*="mt-flow-"]` in the `:not()` on the element that
would receive the margin, so an explicit rung wins **by exclusion, not by
specificity**. The owl is (0,3,0) and a utility is (0,1,0), so escalating
specificity would never have worked.

Consequence worth knowing: only `mt-flow-*` disarms the rules. `mb-flow-*` does not.

## The rules (what's actually in `flow.cjs`)

Six numbered groups, fifteen declarations. Later rules win at equal specificity —
**ordering is load-bearing**.

1. **base** — every visible sibling → `--flow-default`
2. **block objects** (`figure, img, table, pre, blockquote, .chart`) → `--flow-loose`
   above **and** below (two rules)
3. **before headings** — `h1, h2, .title-1, .title-2` → `--flow-section`;
   `h3, h4, .title-3, .title-4` → `--flow-loose`
4. **stacked headings** (`heading + heading`, incl. `[class*="title-"]`) → `--flow-tight`
5. **4b · companion coupling:**
   - `heading + :is(.subtitle, .subhead)` → `--flow-tight`
   - `.eyebrow + heading` → `--flow-tight`
   - `prev + .eyebrow:has(+ heading)` → `--flow-section` (the break moves **above**
     the eyebrow — the eyebrow is the top of the titling cluster)
6. **coupling & lists** — `figure > figcaption` → tight; `li + li` and `li > ul/ol` →
   tight; `dl > dd` → tight, `dl > dt` → default, `dl > dt:first-child` → 0

Headings in groups 4–5 include `h1..h4`, `[class*="title-"]`, `.display`,
`.headline`, `.page-head`, `.section-head`.

Two structural details:

- `:is()` not `:where()`, so the context class carries (0,1,0) and beats element
  resets like `p { margin: 0 }`.
- `:not(.sr-only, [hidden], template)` on **both** ends of every sibling pair, so a
  collapsed or conditionally-rendered sibling never injects a phantom gap and never
  becomes the thing a real element couples to.

**Ten of the rules key on typographic selectors.** Only rule 1 is element-agnostic.
This is the mechanical reason `flow-product` under-delivers in `div`-based markup —
and the reason **using the right role class is what earns the rhythm**:

```html
<!-- Do — rule 5 sees a companion, applies tight -->
<h2 class="section-head">Rough sleeping</h2>
<p class="subtitle">Quarterly</p>

<!-- Don't — visually near-identical, invisible to every rule, gets default -->
<h2 class="section-head">Rough sleeping</h2>
<p class="body-sm text-color-text-muted">Quarterly</p>
```

## Coupling: two mechanisms

- **By nesting** (the spec's canonical mechanism): a companion lives inside a
  compound-unit wrapper with its primary (`figure`/`figcaption`), invisible to the
  owl because it is a child of `figure`, not of the flow root. The wrapper
  participates in flow as one block.
- **By sibling rule** (what we chose for titling clusters): flat markup where a
  `.subtitle`/`.subhead` after a heading and an `.eyebrow` before one snap to
  `--flow-tight`. Keeps authors writing flat markup, and matches how stacked
  headings already work.

> **Spec debt:** the spec's _Content Flow_ section still documents two rules, a
> two-class `.flow` contract, and "wrap companions with their primary" as the only
> mechanism. Reconcile when next touching it.

## The ownership question

Replaces the older rhythm-vs-construction gate, which failed because it asked for a
judgement about a gap's _nature_:

> **Does this gap exist because two things sit next to each other, or because one
> thing has an inside?**

Next to each other → the **stack** owns it → flow rung.
Has an inside → the **component** owns it → `--spacing-{n}`.

Shorter: **if the children are a stack of blocks it's flow; if they're a structure
it's construction.** A card's contents stack; a form's fields stack. A table's cells
don't; a button row doesn't.

Third owner: **horizontal gaps between tiled objects are grid-owned** —
`.grid-gutter` / `.grid-gutter-fluid`, not construction. See `references/layout-grid.md`.

Flow owns the **vertical axis of a flow participant**: sibling gaps and vertical
edge padding. Construction owns the box — horizontal padding, uniform padding,
component interiors.

## Gotchas

- **Wrapper divs sever flow.** The rules match direct children only. Single biggest
  cause of "flow doesn't work". Flatten unless it is a genuine compound unit.
- **Never put a rung on a first child** — no gap to size, and `margin-top` collapses
  through a plain block parent but not a flex one.
- **Don't combine a context class and `gap-flow-*` on one element** — they add.
- **`product` ≠ `flow-product`.** Typography family vs spacing ramp; same word, two
  systems. Most surfaces want both.
- **`.chart` is in both systems on purpose.** It names a typography context _and_
  appears in flow's block-object list beside `figure`/`table`/`pre`. A chart in prose
  wants both chart typography and generous surrounding space. Reported as a
  collision once; it is not one. **Do not rename it.**
- **Metric clusters read tighter than the rung** — metrics use near-1 line-height for
  label alignment, so the visible gap under a rung differs from a text stack.
- **A chart container's slot is not a flow stack** — a plot's internal margins are
  the plot's own and must not be re-expressed as flow rungs.
- **Alignment spacing is exempt** — e.g. `pl-5` on nested checkboxes derives from the
  control's glyph geometry, not from a scale.

## Not implemented (spec-only — don't build against)

- **`--flow-leading`.** The spec and older skill copy claim `flow-compact` tightens
  body-tier leading to ~1.3. There is no such variable anywhere in `packages/themes`.
- **Hero proportional spacing** (`.display { margin-block-start: 0.75em }`). Not in
  the plugin.
