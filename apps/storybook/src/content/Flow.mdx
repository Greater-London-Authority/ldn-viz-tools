# Flow

Flow is the vertical space between stacked blocks. A container declares a flow context, and the context sets the space between its direct children.

The reasoning is on the [Flow foundation page](https://greater-london-authority.github.io/ldn-viz-tools/).

## Declaring a context

```html
<article class="flow-spacious">…</article>
<section class="flow-standard">…</section>
<div class="flow-compact">…</div>
```

The class sets a value for each of the four steps (see below) and spaces the element's direct children.

Two typesets also set a context: `typeset-longform` sets `flow-spacious`, and `typeset-product--formatted` sets `flow-standard`. `typeset-product` sets no flow, so add a flow class beside it when its children are a stack.

Contexts nest, and the innermost applies. Outside any context, the steps take the `flow-standard` values from `:root`.

A component whose spacing must stay the same wherever it is placed declares its own context. Flow from outside doesn't reach inside it.

## The four steps

Each step names how closely two blocks are related. The context sets the distance.

| Step      | `flow-spacious` | `flow-standard` | `flow-compact` |
| --------- | --------------- | --------------- | -------------- |
| `tight`   | 4px             | 4px             | 4px            |
| `default` | 16px            | 8px             | 4px            |
| `loose`   | 24px            | 16px            | 8px            |
| `section` | 40px            | 24px            | 8px            |

`flow-compact` is for small spaces. In it, `tight` equals `default` and `loose` equals `section`, because a small surface can't show four different gaps.

The values come from Figma through Style Dictionary, as the `--flow-*` properties in `tokens.css`. A component should not repeat one of these numbers.

## Steps from the markup

In every flow context, and in `typeset-longform` and `typeset-product--formatted`, the step above each child is chosen from its element or class. An article needs no spacing classes:

```html
<article class="typeset-longform">
	<h2>Air quality</h2>
	<p class="subtitle-sm">Rolling 24-hour mean</p>
	<p>Concentrations fell across every monitored borough…</p>
	<figure>
		<img src="/no2.svg" alt="Nitrogen dioxide concentration" />
		<figcaption>Source: LAEI 2019</figcaption>
	</figure>
	<h3>Method</h3>
	<p>Readings are taken hourly…</p>
</article>
```

The rules are the Flow rules section of `system.css`, generated from `flowRoles` in `packages/themes/sd/system.config.js`. In this table a heading is any of `h1` to `h5`, `display-*`, `headline-*`, `title-*` and the title aliases.

| Child                                                                                                         | Step above it |
| ------------------------------------------------------------------------------------------------------------- | ------------- |
| Any child after the first                                                                                     | `default`     |
| `figure`, `img`, `table`, `pre`, `blockquote`, `.chart`, and the child after one                              | `loose`       |
| `h1`, `h2`, `display-*`, `headline-*`, `.dashboard-main-title`, `.dashboard-section-title`                    | `section`     |
| `h3`, `h4`, `h5`, `title-*`, `.card-title`, `.chart-title`, `.table-title`, `.header-title`, `.sidebar-title` | `loose`       |
| A heading straight after another heading                                                                      | `tight`       |
| `subhead-*`, `subtitle-*` or a subtitle alias straight after a heading                                        | `tight`       |
| A heading straight after an `.eyebrow`                                                                        | `tight`       |
| An `.eyebrow` straight before `h1`, `h2`, `display-*`, `headline-*` or a dashboard title                      | `section`     |
| `figcaption` in a `figure`                                                                                    | `tight`       |
| `li + li`, and a list nested inside an `li`                                                                   | `tight`       |
| `dd` in a `dl`                                                                                                | `tight`       |
| `dt` in a `dl`, except the first                                                                              | `default`     |

The subtitle aliases are `.card-subtitle`, `.chart-subtitle`, `.table-subtitle`, `.dashboard-main-subtitle` and `.dashboard-section-subtitle`.

For debugging: the rules use `:is()` on the context class, so they win over element resets such as `p { margin: 0 }`. Every rule skips `.sr-only`, `[hidden]` and `template` at both ends, so a hidden sibling gets no space and nothing is spaced from it. The rules for direct children also skip an element with an `mt-flow` class.

## Role classes set the step

Most rules match the role class as well as the element, so choosing the right typography role also gives the right space.

```html
<!-- A heading and its subtitle: tight -->
<h2 class="title-lg">Rough sleeping</h2>
<p class="subtitle-sm">Quarterly</p>

<!-- Looks similar, not matched: default -->
<h2 class="title-lg">Rough sleeping</h2>
<p class="body-sm text-color-text-muted">Quarterly</p>
```

## Setting a step by hand

A `div` matches only the `default` rule, so every gap between `div` children is `default`. Use the flow utilities to set a step where it matters:

```
mt-flow-tight     mt-flow     mt-flow-loose     mt-flow-section
gap-flow-tight    gap-flow    gap-flow-loose    gap-flow-section
```

`mt-flow-*` goes on the element that needs space above it. `gap-flow-*` goes on a flex or grid container that is not itself a flow context.

```html
<section class="flow-standard typeset-product">
	<h2 class="title-lg">Monitoring sites</h2>
	<p class="subtitle-sm">Twelve active sensors</p>

	<div class="mt-flow-section">…</div>
</section>
```

An `mt-flow-*` class replaces the step the rules would give. The rules for direct children skip an element with one, so no extra specificity is needed.

The utilities resolve against the nearest context: `mt-flow-section` is 24px in `flow-standard` and 40px in `flow-spacious`. If a gap must be the same size everywhere, use the spacing scale instead.

There are no utilities with a context in the name, such as `mt-flow-standard-section`. That would be a fixed gap, the same as `mt-6`. A component that needs a fixed density declares its own context.

## Flow, grid or spacing

| Gap                              | Set by                                 |
| -------------------------------- | -------------------------------------- |
| Vertical, between stacked blocks | A flow step                            |
| Horizontal, between tiled items  | `grid-gutter` or `grid-gutter-fluid`   |
| Inside a component               | Spacing: `p-{n}`, `mt-{n}` and similar |

If a container's children are a stack of blocks, use flow. If they are parts of one structure, such as a table's cells or a button's icon and label, use spacing. A card's contents and a form's fields are stacks. A table's cells are not.

There are no padding utilities for the steps. Padding is space inside a component.

## Things to avoid

- A wrapper element between the context and the blocks. The rules match direct children only, so the blocks inside the wrapper get no space. This is the most common reason flow seems not to work.
- `mt-flow-*` on a first child. There is nothing above it to space from, and the margin can push the whole container down.
- A context class and `gap-flow-*` on the same element. The margin and the gap add together.
- Margins in other directions. Only `mt-flow-*` and `gap-flow-*` exist.
- Flow steps inside a chart. A plot's internal margins belong to the plot. `.chart` is matched by flow as a block that gets the `loose` step.
